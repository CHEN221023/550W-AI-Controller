# V4.5 Beta 时间设置与中央粒子修复

日期：2026-10-03。产品版本 `4.5.0-beta`，Windows 文件版本 `4.5.0.0`。

## 参数与配置

- 界面只保留“中央粒子待机时长”“粒子 → 550C 总时长”“550C 完整停留时长”三个开场时间参数，均以毫秒输入。
- 默认值为 350 / 1200 / 450；总时长包含待机，重组时间严格取总时长减待机。已有整体时间倍率继续统一作用于这三个时长，帮助文字明确说明。
- 总时长必须严格大于待机。全局保存、独立保存、批量应用在写入前校验，中文提示保留原输入。
- 旧配置按字段存在性迁移：旧待机 A、旧重组 B → A、A+B，完整停留保留。对全局与每个应用的独立配置分别迁移；已有新字段不会再次相加。配置 schema 升为 4。
- `LogoRevealMs` 只用于旧配置迁移；用户界面与播放时钟不再读取它作为额外重组等待。被删除的机器人/扫描参数没有重新出现。

## 待机、预加载与时钟

发现的额外等待来自原生静态首帧到网页初始化之间的时间，以及网页接管后又从零开始待机。现在以原生首次成功绘制的 Stopwatch 时间为起点，将已流逝时间交给网页，交接确认不再重置时钟。

原生覆盖层只在网页准备期间绘制同一批粒子与同一阶段进度；网页接管后停止计时器并释放画笔、图形数据。原有遮盖守卫与交接顺序保留。没有新增常驻动画服务。

待机在既有粒子位置上叠加不同相位的缓慢微动，水平变化上界 3px、垂直变化上界 2.4px，没有大量 DOM、滤镜或新粒子群。起始位置与 V4.4 一致。

原版 550C SVG 的透明栅格缓存和目标采样点由构建脚本生成，供准备画面与网页复用；不使用截图贴图或重新绘制标识。WebView2、图形数据、音频、字体与 HUD 准备并行进行。音频准备挂起也不阻塞开场时间线，较晚网页接管继续当前进度。

保留后续粒子打碎、HUD 与交接逻辑。若极慢设备直到前半段结束仍未完成 WebView2 初始化，网页只能从已流逝的进度继续；不人为延长用户设置，也不保证该异常硬件条件下所有中间帧均有显示。测试不将浏览器虚拟时钟结果视为外部屏幕测量。
