# V4.4 Beta 启动响应专项补丁

日期：2026-10-02。产品版本 `4.4.0-beta`，Windows 文件版本 `4.4.0.0`。

## 实际修复

- 核查 V4.3 的第一有效阶段已是 `PARTICLE_RESIDUE`。未发现扫描/机器人残余阶段、空状态或时间轴占位；本版本没有把已经删除的代码重复计为新修复。
- 轻量 GDI 覆盖层使用原 `residue(t=0)` 的位置、数量、尺寸、种子和配色公式绘制静态首帧。纯黑与粒子在同一次绘制提交，不等待 WebView2。仅增加首帧位图，不建立后台动画或另写粒子时间轴。
- 动画宿主准备 WebView2 时继续保持同一首帧。网页在发出 `VISUAL_READY` 之前绘制实际粒子帧；原提交确认、覆盖守卫、透明压缩交接保持。
- 移除首帧对音频预载的等待；音频引擎、事件与后续声音保持。
- 被动路径在确认进程符合配置后优先启动覆盖层；不必等目标窗口创建或就绪。路径/标题匹配约束保留；状态机防止进程、辅助进程和稍后窗口重复触发。
- WMI 进程事件优先。订阅不可用时，每 200ms 只检查配置中的目标进程名，首次观察建立基线；不重播已经存在的应用。原 5 秒完整核对仍保留。
- 优化快捷启动把目标启动操作移出界面线程，避免它阻塞 Overlay 创建。零/正偏移由首帧绘制通知放行；既有偏移设置保留，超时故障最多 1 秒后放行应用，没有正常路径固定等待。
- 版本、界面角标和更新日志更新到 V4.4 Beta。

## 三个时间点的含义

- `START_T0`：记录进程检测回调或 Managed Launch 的 Stopwatch 时间戳。
- `OVERLAY_T1`：原生绘制完成，并在 DwmFlush 成功后记录提交时刻及 T0→T1。
- `PARTICLES_T2`：确认绘制包含中央粒子，记录同一合成帧。黑底与粒子同帧时 T1→T2 为 0；它表示同次帧提交，不是外部高速摄影测量。
- 合成同步失败/超时时，日志标记 `unavailable` 和 `compositorConfirmed=False`，不伪造显示完成数据。

目前没有 Claude 实机 T0/T1/T2 结果。日志功能已编译，但下述内部数据不冒充实机数据。

- 定向状态测试：22/22 通过。覆盖进程先行、晚到窗口去重、已有应用、禁用配置、Managed Launch 去重、启动崩溃退出及后续重新打开。
- 离屏网页检查：3/3 通过。六个对应时刻的粒子画布和 550C 缓存与 V4.3 像素一致；后续完整 HUD 与交接完成，无脚本错误。
- 模拟音频预载一直挂起时，网页仍在 442.1ms 内提交可见中央粒子帧，18,505 个非透明采样像素、纯黑背景。这个数是网页准备时间，不是原生 Overlay 后的空黑屏时间。
- 原生静态首帧生成：11.30ms；中央亮像素 18477，中心外纯黑。原生 GDI 与 Canvas 光栅化可能有细微抗锯齿差异，不宣称两种渲染器逐像素相同。

- Portable 使用独立空配置后台启动、退出成功，退出码 0，无 ERROR/崩溃，无设置窗口、无目标应用和全屏动画。
- 这些定向检查首次均通过，没有重复运行无关全项目测试。

## 桌面验收限制

用户指定 Claude，并禁止关闭/重启 ChatGPT、Codex 与任务相关进程。准备了仅含 Claude 的隔离配置和测试快捷方式，未改真实用户配置。

Windows Computer Use 请求 File Explorer 与 Claude 的应用控制授权均超时，未完成任何应用输入动作。因此原始 Claude 启动与优化快捷方式的真实 Overlay/闪屏验收均为 **未完成**，没有记录实机延时，也没有用浏览器/fixture 结果代替。ChatGPT、Codex、旧版常驻 Controller 与其他现有应用没有被退出或重启。

该限制明确随成品交付。真实桌面两条路径仍需在应用控制可用后验收；未绕过权限或安全限制。

中央粒子及后续逐帧算法、550C 原图形结构、多窗口 HUD、界面与配置架构、Overlay 守卫、窗口呈现、关闭和交接函数保持。有效动画参数及时间倍率保持。

V4.3 Beta 原成品和源码包保留；修改前文件备份在工作区 `work/v44-before`。
