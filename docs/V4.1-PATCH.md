# V4.1 动画修复补丁 · 4.1.0

发布日期：2026-10-02。基于现有 V4 增量修改，未重建主工程。

## 修复内容

- 移除四角取景框。四个内缩定位点位于逻辑画布 18%/82%、22%/78% 附近，细线向中心汇聚；随后主扫描贯穿机器人全高，扫描线与裁切遮罩使用同一进度。
- core.png 文件完全不变，SHA256：51a26921618ac45089320b03ed1ae3bc76538bfbca5709ecd1fa4f18266d833c。文字、黑位、550C 原路径和后续错位 HUD 布局保持。
- 核心阶段由一个总时长按比例推进，取消固定 240+620+260+180 毫秒的额外入场时间；原“核心独立停留”字段改为准确的“核心阶段总时长”，配置字段仍为 CoreHoldMs。默认 650 毫秒。
- 两段粒子共享同一个画布、700 个默认粒子的池和持续帧循环。准备期生成可复用纹理，按红白颜色批量绘制；各阶段不重新创建粒子或调整画布尺寸。画布维持 1920×1080，不按高 DPI 无限制放大。
- 550C 仍使用原始 SVG 6 条路径及滤镜，只在正式播放前栅格化为透明渲染缓存，避免第一次显现时进行昂贵栅格化。机器人图像未修改，550C 没有使用用户截图贴图。
- HUD 的 47 个节点、初始画面和声音在正式开场前准备；移除额外的 HUD 固定透明度过渡，改为按用户配置的交叉显现进度推进。
- 原生窗口全程保持不透明，等待画面提交后才启动网页时间轴；原生首帧作为安全背景留到正式交接。动画活动期间通过非注入式 WinEvent 通知维护覆盖顺序，不修改目标程序。
- WebView2 的 GPU/辅助进程属于可自动恢复的退出时，不再立即关闭遮罩。主渲染器/浏览器致命故障仍安全退出，超时和退出路径保留。
- 就绪停留按 ReadyMs 执行；可选语音不会再增加一个隐藏的最小时长。设置很短时，未播完的语音会随动画结束释放。

时间换算为“阶段设置 × 整体时间倍率”；最短启动时长仍是单独的下限，等待目标应用就绪也仍然生效。两者不是阶段时间的隐藏硬编码。

## 必要验证结果

- 两组短/长时间与扫描同步检查通过。核心阶段：500ms 实测 494ms；1600ms × 1.5 实测 2395ms。其余 180ms / 975ms 阶段误差在一个采样帧范围内。
- ReadyMs 语音边界检查通过：1600ms 模拟语音没有强行延长 50ms 的就绪停留。
- 扫描遮罩与扫描线位置同步，始终复用一个粒子画布；前半段背景持续不透明纯黑，机器人与 550C 不重叠；原 9 个窗口和 47 个节点检查通过。
- 同一离屏基线、相同默认粒子数：粒子相关阶段最大帧间隔从约 215.1ms 降至约 45.1ms。逐粒子 fillRect 调用从 436307 次改为 2074 次批次填充。修补后长任务仅记录在准备期。该测试不能替代用户机器上的实际 WebView2 帧率验收。
- Controller 与 Animation Release 编译通过，版本 4.1.0.0；Launcher 和语音工作进程沿用现有脚本编译。
- 原始 BOOT、APP、换算后的 CSS 保留检查通过。

## 原生运行验收限制（未通过，不计入成功项）

最初独立桌面/屏幕外探针还遇到了测试通信等待问题，已修正探针读写顺序。后续真实 WebView2 进程出现 GpuProcessExited（0xC0000022），软件渲染探针同样失败；修复 GPU 可恢复事件处理后，最终出现 RenderProcessExited / LaunchFailed / exit 49。

因此原生覆盖顺序检查未进入完整动画，不能声称“真实 ChatGPT 闪屏已实测消失”或“原生运行验收全部通过”。本包提供已编译的修复和通过的离屏证据，真实 Windows 客户端路径仍待运行环境允许 WebView2 子进程正常启动后验收。没有操作真实 ChatGPT 客户端，没有全屏抢占桌面测试。

参考：[WebView2 进程失败类型](https://learn.microsoft.com/en-us/dotnet/api/microsoft.web.webview2.core.corewebview2processfailedkind)、[非注入式 WinEvent 通知](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwineventhook)。
